# DailyGlance 应用设计规范

本规范是 DailyGlance 视觉语言、共享组件和页面级复合组件的唯一语义规则源。`assets/css/dailyglance.css` 是规范的可执行实现；HTML 与 JavaScript 只负责使用组件和填充状态，不另建一套视觉规则。

## 目标与边界

- 产品以电脑端高密度看盘为主，帮助新手每天快速看清状态、动作、风险和失效条件。
- 信息层级优先于装饰效果：先保证结论、数据、状态和操作可扫描，再考虑视觉强化。
- 全应用共用同一套颜色、间距、圆角、字号和动效 Token；页面可以有专属布局，但不能另造基础视觉体系。
- 首页在窄屏下提供“大盘＋本机自选股”精简浏览版；不把完整电脑终端等比缩小，也不在手机端扩展板块趋势、回测、性能诊断和独立策略查看器。
- 产品只提供深色主题；根页面声明 `color-scheme: dark`，原生控件不得自行切换成浅色外观。
- 本文记录稳定设计契约，不复制每一条 CSS；最终像素实现仍以 `assets/css/dailyglance.css` 为准。

## 变更同步边界

以下改动必须在同一轮同步本规范：

- 新增、修改或删除颜色、字号、间距、圆角、动效等 Design Token。
- 修改共享组件的结构、尺寸基线、视觉层级、交互状态、语义变体或可访问性约束。
- 新增可复用组件，或新增像“板块趋势卡片”这样拥有稳定结构和语义状态的页面级复合组件。
- 改变上涨、下跌、警告、信息、失效、禁用等状态的颜色或表达规则。
- 改变弹窗滚动、背景效果、动效策略等可能影响性能或可操作性的规则。

以下改动通常不需要更新本规范：

- 不改变组件契约的局部间距、对齐、截断或兼容性修复。
- 纯文案和数据内容调整。
- 仅修复实现与本规范不一致、且规范本身没有变化的 Bug。

若实现与规范不一致，先判断是实现偏离还是规范确需升级；确认改变设计契约时，代码、规范与对应回归必须一起更新。

## Design Token

Token 定义在 `assets/css/dailyglance.css` 的 `:root`，所有新组件优先使用这些变量。

### 颜色与语义

| 语义 | Token | 用法 |
| --- | --- | --- |
| 上涨、积极、增加风险 | `--up-color` / `--red` | A 股上涨、积极状态、盈利强调 |
| 下跌、消极、降低风险 | `--down-color` / `--green` | A 股下跌、弱势状态、负向变化 |
| 主操作、焦点、选中边界 | `--blue-action` / `--blue` | 主按钮填充、焦点轮廓、选中边界；`--blue` 仅作兼容别名 |
| 信息文本、链接、栏目提示 | `--blue-text` | 深色表面上的小号蓝色文字，保证文本对比度 |
| 警告、混合、待确认 | `--yellow` | 风险提醒、混合状态、缓存与待确认状态 |
| 页面背景 | `--dark-bg` | 应用底层背景 |
| 面板背景 | `--sidebar-bg` | 主面板、卡片和弹窗表面 |
| 内层表面 | `--inner-bg` | 指标格、列表项和卡片内部区域 |
| 主文本 | `--text-main` | 标题、关键数据、主要结论 |
| 次文本 | `--text-dim` | 标签、说明、辅助证据 |
| 边框 | `--border-color` / `--border-light` | 组件轮廓和内部弱分隔 |

积极、警告、信息等弱背景统一使用 `--bg-up-light`、`--bg-down-light`、`--bg-blue-light`、`--bg-warn-light`。新组件不得因页面不同重新定义同义颜色。

### 间距、圆角与字号

- 间距以 4px 为基础单位，使用 `--space-1` 至 `--space-12`；共享组件不新增同义间距变量。
- 圆角使用 `--radius-sm`、`--radius-md`、`--radius-lg`。胶囊状态可以使用完整圆角。
- 字号使用 `--text-xs` 至 `--text-hero`。数字需要稳定对齐时叠加 `.mono`，正文继续使用系统中文字体栈。
- 1px 分隔线、图标几何尺寸、特殊状态标记和数据驱动颜色可以保留必要的精确值；新的可复用视觉值应优先沉淀为 Token。

### 动效

- 常规反馈使用 `--transition-instant`、`--transition-fast` 或 `--transition-normal`，只强化状态变化，不延迟操作。
- 新增组件优先明确过渡属性，避免无边界的重绘。
- 禁用和加载状态必须保持可辨认，不能只依赖动画传达状态。
- `prefers-reduced-motion: reduce` 下关闭价格脉冲、旋转加载等非必要动画，并把其他过渡压缩到接近即时反馈。

## 布局规范

- 顶部栏默认使用左侧 260px、中央自适应、右侧 350px 的三段结构；1024–1180px 窄桌面允许侧栏收紧到 248px / 338px，并同步主工作区列宽。
- 大盘与自选股工作区保持“左侧导航—中间图表—右侧结论”的三栏路径。
- 独立内容工作区使用可滚动页面壳，内容宽度不超过 1180px，页头、章节和边界说明保持同一信息层级。
- 1024px 是完整三栏终端的最小支持宽度；1024px 必须保持工具栏无横向溢出。宽度不超过 1023px 时，首页正常初始化同一套行情、缓存和策略链，但切换为单栏精简浏览布局；独立策略查看器仍只显示电脑端提示层。
- 窄屏首页的顺序固定为：吸顶品牌与大盘/自选入口 → 横向标的轨道 → 数据新鲜度与价格 → 每日结论与关键依据 → 近 90 个交易日的日 K 主图 → 风险声明。页面只纵向滚动，不允许整页横向溢出。
- 窄屏图表只创建主 K 线实例，默认日线、90 个交易日和 `MA5 / MA20 / MA60`；成交量、MACD、KDJ、周线、范围与均线选择仍属于电脑端。横向触摸用于浏览历史 K 线，纵向触摸不得阻断页面滚动。
- 页面专属布局可以使用业务前缀，基础操作、状态和表面样式必须复用共享组件或 Token。

## 共享组件

### 导航与操作

- `.nav-btn`：顶部一级导航，包含默认、悬停和当前状态。
- `.icon-btn` / `.icon-btn-label`：图标操作与图标文字操作，统一边框、圆角、禁用和按压反馈。
- `.segmented-control` / `.seg-btn`：周期、范围等互斥切换。
- `.nav-capsule`：面板内的小型分段操作。

### 内容表面

- `.terminal-block`：默认内容容器；`.no-bg` 只用于容器结构仍需保留但不需要表面的场景。
- `.block-title`：内容块标题和弱分隔，不通过页面内联样式另造同级标题。
- `.action-panel`：每日结论和动作表面，使用 `.panel-bull`、`.panel-bear`、`.panel-warn`、`.panel-info`、`.panel-neutral` 表达语义。“个股每日结论 / 大盘每日结论”标题后固定以弱化小字标注当前策略简称：稳健、波段、突破、综合。整块状态色条与染色背景只属于正式结论/动作组件，观察、排行和数据概览卡不得复用这套视觉语言。
- `.level-pill`、`.index-dash-card`、`.signal-row`：紧凑数据项，遵循主值突出、标签弱化和内层表面一致的规则。
- `.data-status-pill`、`.wl-status`：短状态标记；颜色必须与状态语义一致。缓存属于数据新鲜度，不默认等同风险或警告；同一快照的缓存状态由页面或分组数据所有者统一显示，不在每个子项重复标记。
- 顶部一级导航的当前项同步 `aria-current="page"`；周期、范围、策略选择等互斥按钮同步 `aria-pressed`，不能只依赖 `.active` 视觉类。

### 列表与输入

- `.nav-list-item`：指数和自选股列表项，共用默认、悬停、选中、拖拽和不支持状态；没有嵌套操作的指数行使用原生按钮，自选股行通过名称与状态区域提供独立键盘选择入口，不能牺牲拖动和删除按钮的语义。
- `.stock-search` / `.stock-suggest`：搜索输入与建议列表，焦点使用统一蓝色轮廓；输入与列表遵循 `combobox` / `listbox` / `option` 关系，并同步展开和当前选项状态。
- 窄屏下 `.nav-list-item` 放入横向轨道，当前标的切换后必须滚入可见区；自选股删除入口必须常显，拖拽排序隐藏。搜索、主导航和关键操作的触控区不小于 44px，搜索输入在手机上不小于 16px 字号。
- `.ma-checkbox` 保留可聚焦的原生复选框，只在视觉上隐藏输入；键盘焦点显示在完整标签上，不能用 `display:none` 移除原生控件。
- 新增可复用样式不得写入 `style` 属性；只有数据驱动颜色、动态可见性或无法静态表达的几何值可以例外。

### 弹窗与滚动

- `#settingsPanel`、`#helpPanel`、`#perfPanel` 共用弹窗面板结构；`.sg-body` 是唯一有界滚动容器。
- `#settingsOverlay`、`#helpOverlay`、`#perfOverlay` 是可滚动大弹窗遮罩，必须关闭 `backdrop-filter`，避免滚动时持续重绘背景。
- `#customModal` 只承载小型确认或提示，可以保留轻量背景模糊；不得把长内容放入该组件。
- 关闭状态的弹窗遮罩必须同时隐藏可见性并退出键盘顺序，不能只依赖 `opacity` 和 `pointer-events`；关闭按钮必须提供明确的 `aria-label`。
- 大弹窗使用 `dialog` / `aria-modal` / 标题关联；打开后焦点进入弹窗，Tab 保持在当前弹窗内，关闭后回到触发控件，方向键不能继续操作背景图表。
- 滚动区域使用 `overscroll-behavior: contain`，面板本身负责裁切，标题栏不跟随正文滚动。

### 反馈

- `#loading` 只用于阻塞式加载，文案说明正在发生的动作。
- 主行情无可用历史数据时，图表与右侧结论同时进入明确错误态，并提供“重新加载当前数据”；不能留下空白结论区。
- 自选股为空时，左栏搜索框是输入所有者，中间工作区是唯一任务型空态和 CTA 所有者，右侧结论栏隐藏；不得在三栏重复解释同一空态。
- 设置弹窗只负责选择应用策略和进入独立策略页，不复制完整信号积分配置。策略查看器必须同时标明“应用当前”和“正在查看”，只读浏览不得改写应用策略。
- Toast 用于非阻塞结果反馈；危险操作必须通过确认弹窗，不用 Toast 代替确认。
- 所有可操作控件必须具有 `:focus-visible` 状态，不能只提供鼠标悬停反馈。

## 板块趋势复合组件

板块趋势页复用全局 Token 和共享操作组件，下列结构登记为稳定的页面级复合组件。现有 `external-*` 类名是工作区历史命名，只代表独立内容页壳，不表示数据仍属于外盘模块。

### 页面结构

- `.external-workspace` / `.external-shell`：独立可滚动工作区与最大宽度容器。
- `.external-page-head`：页面标题、状态和刷新操作。
- `.external-section-head`：章节标题、说明和数据范围元信息。
- `.external-boundary-note`：只读观察边界，必须保留且不能弱化为不可见说明。
- 页面模块按证据可靠度固定排序：外部环境推测 → 当前板块状态 → 上涨趋势板块 → 刚刚转强 → 单日异动 → 概念热点 → 使用边界。概念热点不纳入行业趋势统计，必须放在趋势分组之后作为辅助观察，不能占据主结果之前的首屏位置。

### 外部环境推测条

- `.external-env-strip` 固定放在页面标题下方、A 股板块概览上方，保持单条紧凑横向结构，不能恢复为抢占首屏的大卡片区。
- `.external-env-strip-item` 固定包含短主题名、主方向加权涨跌、方向箭头和短行业名；完整主题名、主方向/确认项证据和完整行业名放在 `title` 与 `aria-label`。1440px 默认桌面宽度下四组可见信息不得截断，1024px 窄桌面允许行业尾部截断但必须保留主题与方向。
- `.external-env-strip-label` 的时间必须显示美股交易日“美股 MM/DD 收盘”；北京时间获取时间只放在悬浮说明，缓存或日期不一致状态必须显式可见。
- 外盘方向只通过箭头、数值颜色和明确文字表达；各 `.external-env-strip-item` 之间使用中性分隔线，不使用结论式红绿黄状态色条。
- `.external-env-strip-boundary` 必须显示“待 A 股确认”，该条不能使用买入、卖出、仓位或确定性涨跌话术。

### 市场概览卡

- `.sector-summary-grid` 默认四列；1024px 以下改为两列。
- `.sector-summary-card` 固定包含标签、主值和说明。
- `.sector-summary-card` 使用统一中性边框和背景，不使用顶部状态色条或整卡染色；分类通过 `.sector-summary-dot` 小圆点和文字标签表达。
- 主值使用全局大字号和 `.mono`；说明使用次文本，不与主值争夺层级。
- 板块快照生命周期分为 `idle`、`loading`、`ready`、`partial`、`cached`、`error`。只有 `ready` 且真实统计为零时才显示零值；`error` 且无缓存时显示页级错误和重试入口，并隐藏依赖快照的数据分组；`cached` / `partial` 保留可用数据并明确来源状态。

### 概念热点行

- `.sector-concept-list` 是概念热点容器；`.sector-concept-row` 是单条紧凑扫描单元。
- 行内按身份、当日变化、多周期变化和领涨信息排列；名称与数值必须可截断，不能撑破网格。
- 代表股属于辅助证据层：`.sector-concept-leader-name` 使用主文本色和中等字重 `500`，不得使用 `strong` 或与概念标题相同的强调字重；`.sector-concept-leader-code` 使用次文本色、中等字重和等宽字体。名称可截断，代码保持可见。
- 概念热点由章节标题和涨跌数字共同表达；`.sector-concept-row` 使用中性边框，不为每行重复添加黄色状态边线。
- `.sector-concept-empty` 负责空状态，不用空白区域代替。

### 趋势板块卡

- `.sector-trend-grid` 默认两列，900px 以下单列。
- `.sector-trend-card` 依次包含：行业身份与名称、趋势分、三项核心指标、证据、ETF 对应、活跃个股和失效观察。
- 上涨趋势、刚刚转强与单日异动由各自章节标题统一拥有，卡片内不重复显示状态标签或独占一行；卡片的 `aria-label` 保留行业名称、趋势状态和趋势分。只有卡片脱离分组进入混合列表时，才允许在标题旁增加紧凑状态标签。
- `.sector-trend-card` 使用统一中性边框和背景，不使用顶部状态色条或整卡染色。
- `.sector-trend-score` 只展示排序辅助分，不替代状态标题。
- `.sector-trend-metrics` 保持三列等权，标签弱化、数值突出。
- `.sector-trend-etf` 必须区分直接对应、相近参考和暂无稳定对应关系。
- `.sector-trend-candidates` 中的个股是观察证据，不使用按钮或买入式视觉暗示。
- 活跃个股和概念代表股统一清理 `XD`、`XR`、`DR` 除权除息前缀，代码保持原样，避免同一标的在不同页面出现不同名称。
- `.sector-trend-invalid` 必须保留失效观察，放在卡片末尾作为结论边界。
- `.sector-trend-empty` 负责整个分组的空状态。

## 状态与可访问性

- A 股语义固定为红涨绿跌；不得按海外产品习惯反转。
- 颜色只用于强化，关键状态必须同时出现文字或数值。
- 主结论、主操作和焦点使用蓝色；黄色只表达风险、混合或待确认，不能同时承担主操作颜色。
- 蓝色文本使用 `--blue-text`，操作填充和焦点使用 `--blue-action`；白字蓝底主按钮必须维持可读对比，小号蓝字不能直接使用兼容别名 `--blue`。
- 文本与背景必须保持可读对比；次文本不能用于关键结论。
- 键盘焦点统一使用 2px 蓝色外轮廓；新增控件必须加入焦点选择器或使用已有共享组件。
- 可见但不可操作的内容不进入 Tab 顺序；可操作的原生控件、列表选择、均线切换和折叠摘要都必须可通过键盘到达。
- 动态更新区域保留合适的 `aria-live`，图标按钮必须有可读的 `aria-label` 或 `title`。
- 依赖悬浮提示的状态胶囊必须可聚焦，并把完整说明同步到 `title` 与 `aria-label`，键盘用户不能只看到短标签。
- 数据新鲜度遵循“所有者显示”原则：整页同一快照只在页头状态和快照元信息处显示一次；只有子项确实来自不同日期或来源时，才在异常子项单独标记。

## 验证要求

- 只改规范文档：检查文档路由和链接，不需要浏览器视觉验证。
- 改 Token、共享组件或页面级复合组件：运行 `presentation-state` 定向回归，并检查所有使用该组件的桌面路径。
- 改布局、滚动、遮罩或动效：除定向回归外，至少人工检查默认、长内容、空状态和窄桌面宽度。
- 改手机布局或触控：至少检查 375px、390px、430px、768px 和 1023px，确认无整页横向溢出、主导航可用、结论未裁切、只创建主 K 线，且横向图表手势不阻断纵向滚动；同时保留 1024px 与默认桌面检查。
