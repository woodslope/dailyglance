# DailyGlance 产品决策指南

## 核心目标

DailyGlance 的核心不是堆指标，也不是把页面做复杂，而是让刚进入股市的新手每天打开看一眼，就能判断一只股票当前大致处在什么状态。

产品输出优先级：

1. 现在能不能碰。
2. 已经持有要不要继续拿。
3. 当前应该空仓、轻仓、持有、减仓还是清仓。
4. 风险在哪里。
5. 什么条件出现后，当前判断失效。

## 不要重新造轮子

生产策略链路、信号状态、仓位和主图 `B/S` 规则以 `docs/strategy/STRATEGY_DECISION_RULES.md` 为准。

`getNoviceDecisionSummary()` 是展示层摘要，不是第二套策略。它只把既有结论翻译成新手可读文本，不得修改 `position`、`bsMark`、`buySignals`、`exitSignals`、`warningSignals` 或 `scoreGroups`。

## 后续优化方向

后续如果用户说“优化分析”“下一步做什么”“策略还能不能更好”，默认先检查以下方向：

1. 右侧每日结论是否足够清楚。
2. 失效条件是否可执行。
3. 三条依据是否能解释结论来源。
4. 是否存在新手误读风险。
5. 是否有测试保护不改变主图 `B/S`。

不要优先新增 `B/L/W` 信号。新增信号必须先经过 `docs/strategy/STRATEGY_DECISION_RULES.md` 的候选池规则、消融验证和回归测试。

## 特殊行情状态展示规范

A 股行情源可能把临时交易状态写进股票名称，例如：

- `XD`：除息日。
- `XR`：除权日。
- `DR`：除权除息日。

这些前缀属于行情状态，不是股票长期名称。DailyGlance 面向新手时必须把“股票是谁”和“今天有什么特殊状态”分开处理：

1. 搜索建议、左侧自选股名称、固定样本名称统一展示规范股票名，不展示 `XD/XR/DR` 前缀。
2. 内置样本股票优先使用 `STOCK_DATABASE` 的固定全称，例如 `600519` 始终显示“贵州茅台”。
3. 非内置股票可去掉 `XD/XR/DR` 临时前缀后展示原名称；如果后续需要提示除权除息，应另设状态提示，不写进股票名。
4. 该规范只属于展示/命名层，不得改变行情价格、K 线、复权处理、策略结论、`position`、主图 `B/S` 或 `SIGNAL_VERSION`。
5. 新增类似特殊状态处理时，必须补回归测试覆盖搜索建议、加入自选、已有自选缓存渲染三条路径。

除非另有明确需求和复权数据验证，不新增除权除息分析模块；不要把这条名称规范扩展成分红解释、复权修正或价格跳空归因功能。

## 右侧决策面板话术规范

右侧面板面向新手，固定按“结论 -> 推导依据 -> 技术细节”三级渐进披露，不把技术词当作结论，也不让三层重复同一句动作。

个股与大盘共用信号、积分、风险、仓位和 `B/S` 决策链，但必须使用不同的展示语义：

- 个股回答“这只股票现在怎么买、怎么拿、怎么防守”，使用买入、持仓、减仓、离场和建议仓位等表达。
- 大盘/指数回答“当前市场是否适合增加、维持或降低风险暴露”，使用指数动能、风险仓位、市场风险和核心市场环境等表达。
- 大盘结论不得出现“个股信号”“买入依据”“持仓依据”或“再按个股信号考虑开仓”等个股话术；个股结论也不得把自身动作泛化成整个市场的风险暴露建议。
- 这只是展示翻译分流，不得复制策略计算、改变最终 `position` / `bsMark`，或创建第二套指数策略。

- 结论回答“现在怎么办”：状态、动作、仓位、实际驱动原因、限制原因和失效条件。
- 推导依据回答“为什么”：门禁、个股/指数有效信号、风险防守三项事实各解释一个维度。
- 技术细节回答“怎么算”：展示今日/近窗、参与计分/同组去重/观察过滤、风险系数和仓位计算链，默认折叠。

每日结论区固定表达：

1. 状态：说明当前处境，例如“破位防守”“趋势转强”“离场冷静期”。
2. 动作：说明今天该做什么，例如“空仓观望”“只适合轻仓”“继续持有”“降低仓位”。
3. 仓位：显示当前建议仓位百分比。
4. 原因：买入、加仓、持有、减仓或离场时，必须写出真实驱动信号；再说明市场门禁或个股风险为什么限制仓位。积分结果不能替代原因。
5. 失效条件：必须写成可执行条件，例如“买入积分重新达到 X/X 并脱离冷静期后才重新考虑”“跌破防守位则继续空仓/降仓”。

离场与冷静期必须区分展示：买入积分不足导致试探仓退出时，状态写“信号失效”，不得泛化成“破位防守”；当日真实触发强离场时，明确说明从下一交易日起进入 3 个交易日冷静期；冷静期内显示“第 X/3 个交易日、还剩 X 个交易日”；冷静期内再次触发强离场时，明确说明冷静期从下一交易日起重新计时。上述内容只解释既有决策，不得改变离场信号、积分、仓位或 `B/S`。

结论只展示实际参与积分的前 1-2 个关键原因，不显示 `B/L/W` 代码，不罗列完整指标。必须区分“今日出现”和“近窗延续”；观察信号、被过滤信号和同组去重后未计分的信号不得写成买入原因。

近窗积分信号的发生日期与当前所选日期不一致时，结论必须明确信号发生日，不得让用户误读为主图 `B` 当天出现。波段抄底型的信号实例按“触发 -> 窗口有效 -> 失效”单向变化：KDJ 金叉后再死叉属于软失效，默认收盘跌破信号日低点属于硬失效；旧实例失效后不得因指标或价格回升自动复活，必须由新信号重新计分。

股票模式的波段 `B11` 是唯一例外：跌破 B11 信号日低点但未跌破最近确认的结构低点时，结论写“结构未破 / 只适合轻仓”，明确“局部回踩失守、暂停加仓、维持 30% 试探仓”；结论防守位、失效条件、风控依据和技术细节统一展示结构防守位，不并列展示更远的通用止损位。只有收盘跌破结构防守位，才写 B11 硬失效和退出。综合全能、指数、其他 B 信号及真实离场不使用这一例外。

发生失效转换时，结论必须说明信号名称、失效原因、积分变化和仓位动作。软失效不等于立即清仓：30% 试探仓若仅因软失效跌破维持门槛，保留 1 个交易日观察；B11 局部回踩失守按上述双层防守处理；其他硬失效则当日执行防守。技术细节必须保留信号发生日、失效日和“不计分”状态，不得再把失效信号写成当前有效买入原因。

关键推导依据固定翻译：

- 核心建仓门禁：本质仍是单向增仓门禁，只说明门禁是否真实影响本次动作。全面弱势的新仓说明“本次新仓按个股信号执行，不受20%上限限制，后续加仓仍暂停”；已有仓位说明“后续加仓仍暂停，本次未改变已有仓位”。上证、深证、创业板、科创50和北证50只能作为观察信息，不得进入门禁解释。
- 指数动能 / 个股信号：买入时展示“买入依据”，持仓时展示“持仓依据”，未买入时展示“未买入原因”；同时说明实际计分信号、今日/近窗来源和积分阈值。
- 风控/防守：展示当前风险依据、防守位和真实离场/预警信息，不重复结论区的动作口号；B11 局部回踩失守时，以结构防守位替代通用止损位，避免出现两条冲突的退出价格。

技术细节默认折叠，至少包含：仓位计算链、今日原始信号、积分与离场窗口。每个信号必须标明“计分、同组去重、未进入积分、离场、风险或观察/过滤”之一；技术细节只能追溯现有结论，不得生成第二套动作。

### 个股三级内容

- 结论：显示“个股每日结论”，回答买入、持仓、减仓或离场，仓位称为“当前建议仓位”。
- 推导依据：固定为“核心建仓门禁、个股信号、风控/防守”。门禁是外部约束，只有真实限制本次新仓或加仓时才强调限制。
- 技术细节：使用“仓位计算链、今日原始信号、积分与离场窗口”，保留个股高风险上限等个股风控说明。

### 大盘/指数三级内容

- 结论：显示“大盘每日结论”，回答增加、维持或降低风险暴露，仓位称为“当前风险仓位”。
- 推导依据：固定为“核心市场环境、指数自身动能、市场风险/防守”。核心宽基状态是市场背景，当前指数仍按自身动能和风险形成结论。
- 技术细节：使用“风险仓位计算链、今日指数原始信号、指数动能与离场窗口”，风险限制称为指数高风险上限。
- 全面弱势时，大盘说明“本次新建风险仓位按自身动能执行，不受20%上限限制，后续提高风险仓位仍暂停”或“暂停提高风险仓位”；个股说明“本次新仓按个股信号执行，不受20%上限限制，后续加仓仍暂停”或“本次加仓被暂停”。

## 快照样本联动校验

右侧结论或关键推导依据改动后，必须使用 `tests/strategy-baseline-snapshots.json` 的固定样本联动验证展示文案。

每个快照样本都必须能在右侧面板读到：

1. 当前状态：每日结论区要说明“破位防守、趋势转强、离场冷静期”等状态。
2. 当前动作：要能看懂今天是空仓观望、继续持有、先不碰、可积极关注还是规避风险。
3. 当前仓位：展示 `position` 对应的建议仓位百分比。
4. 风险来源：展示风控/防守、风险等级、离场状态或防守观察。
5. 失效条件：展示“失效条件：”，并包含买入积分、防守位或强离场信号等可执行条件。
6. 新手解释：个股关键依据必须出现“买入依据 / 持仓依据 / 未买入原因 / 观察依据”之一和“风险依据”；大盘必须出现“动能依据 / 维持依据 / 动能不足 / 观察依据”之一和“市场风险”。
7. 技术追溯：日线技术细节必须包含仓位计算链，并能区分今日/近窗与计分/去重/过滤状态。

该校验只验证展示层表达，不允许改变生产策略链路、`position`、`bsMark`、`scoreGroups` 或 `SIGNAL_VERSION`。

禁止事项：

- 不把“全面多头”直接写成“可以买”。
- 不把观察信号写成买卖指令。
- 不承诺收益，不使用“必涨”“稳赚”“抄底成功”等表达。
- 不新增第二套策略判断；只能翻译既有 `meta`、`decision`、风险和信号状态。

## 验收标准

任何分析展示优化都必须满足：

- 不改变生产策略的最终仓位和主图 `B/S`，除非任务明确要求并同步升 `SIGNAL_VERSION`。
- 能用一句话说明“这个股票现在是什么状态”。
- 能给出明确动作：先不碰、只适合轻仓、继续持有、降低仓位、空仓观望、可积极关注。
- 能说明关键理由和失效条件。
- 回归测试必须覆盖不改变 `position` / `bsMark` 的约束。
