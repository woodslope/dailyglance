# 策略验证与打磨指南

本文只定义生产策略变化的最低验证边界，不定义当前策略、候选结果或发布流程；当前生产规则以 `STRATEGY_DECISION_RULES.md` 为准，协作与沉淀路由见根目录 `AGENTS.md`，发布流程见根目录 `STABILITY_CHECKLIST.md`。

## 适用范围

只有以下真实变化才读本文：新增或删除信号，调整积分、阈值、仓位算法、首次 `B/S`、交易频率，或提出收益/回撤主张。右侧文案、展示翻译、布局和既有决策的语义澄清不默认进入收益研究；它们分别读取产品规则和相关源码。

## 样本、快照与报告

- `strategy-validation-universe.json` 是样本池元数据；当前范围为 97 只股票和 8 个指数，三项核心宽基必须保留。
- `tests/strategy-baseline-snapshots.json` 锁定当前生产输出。候选与基线必须使用同一确认历史、共同截止日和缓存哈希；实时 quote、live overlay 与盘后待确认数据不得进入研究。
- `.local/strategy-cache/`、`.local/strategy-reports/` 与抓取日志是临时生成物，不进入部署包或活跃规则。报告最少记录候选 ID、策略、变体、样本范围、数据哈希、`position`/`B/S` 差异和结论。
- 只有有意改变生产策略或确认历史样本修订时才更新快照；不能只为通过测试直接改期望值。

## 先判断是否需要策略研究

不是所有 `computeDecisionForIndex()` 改动都是策略候选。先按目标分类：

| 类型 | 判断 | 验证边界 |
| --- | --- | --- |
| 展示翻译 | 只改名称、解释或回放透明度 | 不运行策略准入，只做展示回归 |
| 决策语义修正 | 修正已明确的优先级、增量上限或 `B/S` 契约，不发明新信号 | 验证关键转移、固定快照和四策略共用契约；聚合回放只作健全性观察，不设成本/指数分层硬门槛 |
| 信号时机修正 | 调整已有买卖动作的发生时点，目标是修正误卖/漏卖，不宣称必须提高收益或改善回撤 | 候选类别使用 `signal_timing`；做事件级证据、作用域硬边界和组合影响观察，结果可直接进入人工产品取舍，不强制先跑全量 |
| 核心策略变更 | 增删信号、改积分/阈值、改首次 `B/S` 或交易频率，或需要宣称策略收益优势 | 使用本文后续的完整策略研究流程 |

候选类别必须在第一次运行前明确；评估器遇到未知或拼错的 `candidateClass` 直接报错，不得静默回退为收益型或风控型。成本压力、三段时间窗口和股票/指数/行业分层是核心策略变更的研究工具，不阻塞语义或信号时机修正。

## 评估结果与产品决策分离

- `reject` 只表示候选违反了预先声明的核心目标或硬安全边界，不得用一个与目标错配的指标自动否决。
- `ready_for_product_review` 表示作用域和组合损害硬边界通过，收益、回撤和换手已显式列出，由用户根据卖点/买点质量做产品取舍。
- 研究报告的测量结果与最终产品决策分开记录。用户接受已知取舍后，不改写原报告，也不为改一个门槛名称重跑同一批样本。

## 核心策略变更的标准流程

每轮只处理一个策略的一条原子规则，先声明候选 ID、候选类别、允许变化的字段和样本范围；不改生产代码。

1. **快速筛选**：只载入 `seed` 股票与 8 个指数上下文，先观察候选是否产生预期变化和越界。快筛不得先载入97只股票，也不得因信号版本或准入门槛变化自动重建105标的全量基线。
2. **判定停点**：硬边界失败或预声明核心目标失败时才是 `reject`，立即冻结定义并停止。只有指标分类错配、实验捆绑越界或实现与预注册不一致时，才做一次结构性修订；修正流程分类不等于继续调整数值参数。
3. **决定是否全量**：只有核心策略变更、收益/回撤优势主张，或快筛暴露出需要跨样本确认的不确定性时才运行 `--full`。信号时机修正达到 `ready_for_product_review` 后，可由用户直接接受已知取舍并进入生产接入。
4. **本地生产接入**：按冻结定义修改生产代码，只运行受影响回归和固定快照，不重跑已完成的候选研究。日常授权与最小验证统一按根目录 `AGENTS.md` 执行；发布时只引用 `STABILITY_CHECKLIST.md`，本文不重复发布步骤。

### 同快照结构性修订边界

结构性修订是对实验作用域的纠偏，不是对价格、天数、倍数或阈值反复调优。必须同时满足：

- 被拒绝候选保留原 ID、定义哈希、报告和 `reject` 结论，不覆写、不更名复活。
- 新候选必须记录 `revisionOf`、失败证据、删除的越界机制、保留不变的数值参数和允许变化的决策字段。
- 同一被拒候选在同一快照上最多允许一次结构性修订；新候选若再次 `reject`，立即停止，等待新的确认时段或新样本。
- 同快照结构性修订不得改数值阈值，不得因已知样本单独增加行业、标的、日期或行情过滤。
- 对需要宣称策略优势的核心变更，同快照结构性修订仍只是探索性快筛，后续需要非 `seed` 留出样本或全量回放。该要求不自动扩展到语义修正或 `signal_timing` 车道。
- 结构性修订快筛前必须先固定候选定义；运行后不根据结果继续调整并在同快照重跑。

### 卖点与信号时机适配车道

当研究目标是“卖点或买点是否出现在正确时机”，而不是宣称平均回撤必须改善多少个百分点，候选必须使用 `signal_timing`，不得套用 `risk_control` 的“必须改善回撤”目标。收益回退 `1` 个百分点、平均最大回撤恶化 `0.5` 个百分点、换手增幅 `10%` 仅作为报告参考线，不再作为自动否决条件；实际变化必须透明列出，由用户结合买点/卖点质量自行取舍。

- 事件报告优先包含：触发后 1/3/5 日前向收益、最大不利/有利走势、关键价位恢复/失守比例，并单独列出误卖和漏卖；已有足够的定向案例与作用域证据时，不为补齐无关聚合指标重跑全部样本。
- 必须保留结构硬边界：风险事件前零漂移，指数零漂移，不得无根据地新增 `B/S`，不得让全局加仓门禁反过来改变其他无关事件。
- 收益、回撤、换手只作组合影响观察，不作事件时机快筛的自动否决条件；只有作用域越界、指数或其他策略漂移、风险事件前零漂移被破坏、绕过强离场或风险门禁等硬安全边界才自动拒绝。
- 快筛达到 `ready_for_product_review` 后，若用户已接受报告中的收益/回撤/换手变化，可直接进入生产接入；只有事件样本过少、结果方向不稳定或用户要求做收益优势主张时，才增加留出样本或全量回放。

## 缓存、报告与命令

需补数据时显式执行，单轮最多新增 12 个标的。快筛先选标的再载入缓存，并以这些标的的最新共同确认日生成本次快照；候选对照使用当前生产代码在同一快照上实时计算。信号版本、准入门槛、局部缓存更新或新交易日都不再要求重建105标基线；只有样本池或缓存文件映射变化、当前没有可复用的基线元数据时，才运行 `baseline --full`。研究证据的长期归档位置统一见根目录 `AGENTS.md` 的“唯一沉淀路由表”；不输出无关的原始 K 线或完整 JSON。

```bash
# 仅当样本池/缓存文件映射变化或缺少基线元数据时生成
node scripts/strategy-iteration.js baseline --full

# 快速筛选：一次只评估一个策略、候选和变体
node scripts/strategy-iteration.js evaluate --reuse-baseline --screen \
  --strategy 策略名 --candidate 候选ID --variant 变体ID

# 仅在本候选确实需要全量证据时执行
node scripts/strategy-iteration.js evaluate --reuse-baseline --full \
  --strategy 策略名 --candidate 候选ID --variant 变体ID
```

修改 `SIGNAL_RULES`、`STRATEGIES`、`scoreGroups`、权重、阈值或核心决策函数时，需要评估是否改变策略契约；版本和发布规则统一见根目录 `STABILITY_CHECKLIST.md`。只改文档或本地研究记录不构成生产策略变化。

`scripts/strategy-iteration.js` 是正式策略研究的唯一入口。`strategy-autopsy.js` 与 `strategy-autopsy-multi.js` 只作按需诊断，报告写入 `.local/strategy-reports/`，不写入 `docs/strategy/`，也不能替代本指南的准入流程。
